# 发布指南

## 首次推送 GitHub

在 GitHub 创建空仓库，建议名称 `ollama-ui`。创建时不要自动生成 README、许可证或 `.gitignore`，以免与已有文件冲突。

在项目根目录执行：

```powershell
git init -b main
git add .
git status --short
git diff --cached --stat
git commit -m "chore: prepare ollama ui for open source"
```

核对暂存内容仅包含源码、图标、文档、锁文件和工程配置。`.tools/`、`.cache/`、`node_modules/`、`dist/`、`src-tauri/target/`、模型和个人设置应被忽略，不要用 `git add -f` 强制加入。

复制 GitHub 页面提供的真实地址，将下面的占位地址替换后执行：

```powershell
git remote add origin https://github.com/YOUR_NAME/ollama-ui.git
git push -u origin main
```

README 使用相对链接，无需写死 GitHub 用户名。GitHub Actions 只检查和上传构建产物，不会自动创建公开 Release。

## 版本检查

1. 同步 `package.json`、`package-lock.json`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock` 和 `src-tauri/tauri.conf.json` 中的项目版本。
2. 更新设置页版本文案、英文词典和 `CHANGELOG.md`。
3. 确认名称、图标和 `com.localollama.desktop` 数据标识；更改标识需要处理已有配置迁移。
4. 确认图标和新增素材来源及授权，保留第三方代码的许可证声明。

npm 包和 Rust crate 内部仍名为 `local-ollama`，展示名为 `ollama ui`。无需为展示名更改内部 crate、可执行文件名或数据目录。

## 验证与打包

```powershell
npm ci
npm run build
npm test
npm run desktop:fmt:check
npm run desktop:check
npm run desktop:test
npm run desktop:build
```

按 [验证记录](验证记录.md) 完成人工检查，尤其是托盘退出、下载恢复、中文/英文和原生图标。首次推送后检查 GitHub CI 结果。

安装包位于 `src-tauri/target/release/bundle/nsis/`，例如 `ollama ui_0.1.0_x64-setup.exe`。GitHub Actions 的 `windows-installer` artifact 也包含构建产物，需要登录 GitHub 下载。

生成校验值：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath 'src-tauri/target/release/bundle/nsis/ollama ui_0.1.0_x64-setup.exe'
```

当前未配置 Windows 代码签名。若将来签名，证书与密码只放入发布环境或 GitHub Secrets，不存入仓库。

## 创建 Release

1. 合并并确认 CI 通过后创建版本标签，例如 `v0.1.0`。
2. 在 GitHub Releases 选择标签，填写对应更新日志、系统要求和 SHA256。
3. 上传 NSIS 安装包；源码由 GitHub 随标签提供，不上传整个工作目录。
4. 首版可标记预发布，确认安装、升级和卸载后再发布稳定版本。

本地工具链、模型和客户端设置不属于 Release 资产，不将本机开发记录或缓存截图直接作为公开文档。
